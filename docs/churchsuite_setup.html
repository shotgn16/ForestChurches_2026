ChurchSuite Integration (PKCE) — Setup

This project implements ChurchSuite OAuth using PKCE (public-client flow). Follow these steps to configure and test.

1) Register an App in ChurchSuite

  1. In the ChurchSuite developer console create a new OAuth app. Choose a public / PKCE-compatible client if the platform supports it.
  2. Set the Redirect URI to: https://YOUR_HOST/ChurchSuite/Callback (replace YOUR_HOST with your domain or localhost:5001 when testing).
  3. Do NOT rely on a static client secret; PKCE allows public clients.

2) Assign ClientId to a User

  1. The app expects a ClientId per user. You can set this in the UI: Identity → Manage → External Logins (or seed in DB for testing).
  2. For system-level clients you may add a ClientId into configuration, but the implemented flow prefers per-user ClientId stored on ChurchAccount.ClientId and persisted into ChurchSuiteCredential.ClientId.

3) Authorize Flow (what the app does)

1. App generates code_verifier and code_challenge (S256). 2. App stores TempCodeVerifier in ChurchSuiteCredentials row for the user. 3. Redirect to https://login.churchsuite.com/oauth2/authorize?response_type=code&client_id=...&code_challenge=...&code_challenge_method=S256&scope=openid profile email api 4. User logs in at ChurchSuite and approves access. 5. ChurchSuite redirects to /ChurchSuite/Callback?code=...&state=... 6. Callback exchanges code using form fields: grant_type=authorization_code, code_verifier, client_id, redirect_uri → receives access_token + refresh_token. 7. App stores tokens via token service and marks credential IsActive.

4) Debugging & Troubleshooting

  • Redirect URI mismatch: ensure exact match including protocol and path. The code exchange expects the redirect URI set to /ChurchSuite/Callback.
  • Missing ClientId: Authorize page will reject if the user's ClientId is blank — set it via Manage → External Logins or update DB.
  • PKCE verifier missing: the app saves a TempCodeVerifier in DB and may also use session state. If session is lost, callback attempts to recover from DB.
  • Token exchange errors: check server logs (Callback.cshtml.cs logs provider error and response body). Look for provider error in TempData["ChurchSuiteAuthError"].

5) Where Tokens are Stored

Tokens are stored in the ChurchSuiteCredentials table and managed by the token service (Components/Http/ChurchSuiteTokenService and Components/Http/ChurchSuiteService). The centralized token service handles automatic refresh logic when the app needs to call ChurchSuite APIs.
