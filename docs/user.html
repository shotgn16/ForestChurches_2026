User Guide

Summary of core user tasks: registration, managing church profile, adding events, and ChurchSuite sign-in.

Registering

  • Open: /Identity/Account/Register (standard Identity pages integrated in Areas/Identity).
  • Admins can create users via Admin→Users→Register (Pages/Admin/Users/Register.cshtml.cs). The register flow creates a ChurchAccount, optional church information, and sends a welcome email.

Managing Church Profile

  • Users can edit their Church profile via Identity→Manage→ChurchProfile (Areas/Identity/Pages/Account/Manage/ChurchProfile.cshtml).
  • Geolocation helper: /wwwroot/js/churchprofile.js exposes a getLocation() helper which calls a handler to resolve latitude/longitude → address.

Events

  • Manage events from the user interface. Event pages are under Pages/Events and admin event pages are under Pages/Admin/Events.
  • Events can be synced from ChurchSuite when the account is connected.

Signing in with ChurchSuite (for users)

When a user signs in with ChurchSuite the flow uses PKCE (no client secret required). If it's the first time, the app will complete authentication and persist ChurchSuite credentials in the ChurchSuiteCredentials table.
  1. From Register or Manage External Logins, click "Sign in with ChurchSuite".
  2. The app generates a PKCE code_verifier and code_challenge, saves the verifier to the ChurchSuiteCredential.TempCodeVerifier and redirects to ChurchSuite authorize endpoint (Pages/ChurchSuite/Authorize.cshtml.cs).
  3. After login ChurchSuite calls /ChurchSuite/Callback where the code is exchanged for tokens using the saved verifier and client_id (Pages/ChurchSuite/Callback.cshtml.cs).
  4. Tokens are stored by the token service; the app will then attempt to sync profile & events.

Troubleshooting Login

  • Ensure the user has a ClientId set (in the user record). If ClientId missing the authorize page redirects to Manage→ExternalLogins with an error message.
  • If callback reports token exchange errors, confirm the redirect URI exactly matches: {scheme}://{host}/ChurchSuite/Callback.
For more details see ChurchSuite setup and Developer Notes.
