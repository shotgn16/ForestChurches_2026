Admin Guide

This page summarizes the key admin functions and where to find the code that implements them.

User Management

  • Create admin users: Admins can create users from the Admin→Users→Register page (Pages/Admin/Users/Register.cshtml.cs). Passwords are validated with high requirements (min length 12, symbol, numeric, mixed case).
  • Seed super admin: The repository seeds a default SuperAdmin via UsersController.SeedSuperAdminAsync (Components/Users/UsersController.cs).
  • Assign roles: Roles are stored encrypted; role assignment happens on registration (see RegisterModel.OnPostRegisterUser).

Roles & Permissions

  • Role definitions and logic: Components/Roles and Components/Permissions contain system roles and permission checks. Look for AppPermissions and RolesController logic.
  • Authorization policy example: The register page uses [Authorize(Policy = "UserManagement.Write")].

Church Information & Events Management

  • Each user has a ChurchInformation record (Models/ChurchInformation). Admin pages to edit church info are under Pages/Admin/Church.
  • Event CRUD pages live under Pages/Admin/Events. Events sync with ChurchSuite via the ChurchSuiteService.

Email & Templates

  • Welcome and notification emails are sent through Components/Email/*. Templates are in templates/*.html (e.g., templates/registration_complete.html).

Quick Admin Tasks

  1. Create a SuperAdmin via seed (UsersController.SeedSuperAdminAsync) or use the Admin→Invite flow.
  2. Manage roles from Admin→Roles pages.
  3. Review ChurchSuite connections per user under Admin→Users→Edit or Identity→Manage→External Logins.
